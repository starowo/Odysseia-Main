# 处罚公示留痕

在 `config.json` 顶层设置 `punish_archive_channel_id` 为留痕频道 ID。默认 `0`（或不配置）不启用。沿用现有 `server_override`：源服务器的同名键优先于顶层值，可指定不同频道，或设为 `0` 禁用该服务器留痕。无需新数据库。

```json
{
  "punish_archive_channel_id": 123456789012345678,
  "server_override": {
    "987654321098765432": {
      "punish_archive_channel_id": 123456789012345678
    }
  }
}
```

留痕频道可以位于其他服务器，机器人需能访问并发送消息/嵌入内容/附件。发送使用全局频道缓存，缓存未命中时通过 API 获取频道。公示与留痕配置为同一频道时只发送一次。原公示成功后，发送相同 Embed 的副本；图片及其他附件独立复制，保留 `attachment://` 引用。

仅原始标准处罚公示留痕，覆盖管理处罚/踢出/永封/批量永封、永封审查启动/到期自动封禁/撤销、处罚撤销、答疑处罚/永封。同步处罚和同步撤销仍在目标服务器公示，显式标记 `from_sync=True`，不调用留痕函数。私信、命令回执、管理日志、答疑日志不会另外复制。保留原公示频道的解析方式和触发条件；未产生标准公示时不会单独留痕。留痕失败独立记录日志，不中断后续日志或同步。

## 验收

1. 测试服务器 A、B 开启既有双向处罚同步，配置同一留痕频道 C。
2. A 发起处罚：A 原公示一次，B 同步公示一次，C 一次；B 发起处罚时反向结果相同。
3. 直接应用同步处罚或同步撤销：目标公示正常，C 无新增消息。
4. 源公示频道与 C 相同：只一条。将 C 改为另一个服务器中的频道，检查缓存未命中时仍发送。
5. 发送带图片的永封审查并撤销：C 的 Embed 与原公示一致，附件完整。
6. 取消 C 的发送权限后执行批量永封：处罚、原公示和后续同步完成，日志出现留痕发送失败。
7. 删除配置或设为 `0`：恢复只有原公示。到期审查自动封禁同样只为原公示留痕。
